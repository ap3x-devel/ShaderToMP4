ShaderToMP4 local APIAPI locale de ShaderToMP4

ShaderToMP4 --serve[=port] starts an HTTP / JSON API on 127.0.0.1 (default port 8765). It is off unless asked and stops with POST /api/v1/shutdown. The shape of every answer is described in schema.json.

Access

The program writes a 64-character token in serve.token next to the program (and the port in serve.json); both files are removed when the server stops. Every request needs:

Authorization: Bearer <token>
Host: 127.0.0.1:8765        (or localhost)
CaseAnswer
No token, wrong token401
Host other than 127.0.0.1 / localhost, or an Origin header (a web page)403
Unknown address, unknown job404
Method not allowed on that address405
Body not JSON, unknown setting, bad path400 ({"error": "..."})
Body over 1 MB413
Too many jobs waiting, deleting a running job409

The server never listens on another address of the machine and closes a connection whose remote address is not 127.0.0.1.

Endpoints

All under /api/v1. Bodies and answers are JSON (UTF-8).

RequestWhat it does
GET /status`{"program","version","api":1,"state":"idle""busy","queued","running","jobs"}`
GET /settingsevery setting of the settings table, as text
PUT /settings{"width": 1280, "fps": 30}: changes the general settings (strings, numbers or booleans); an unknown key gives 400 and changes nothing
POST /jobs{"path": "C:/shaders/plasma.glsl", "settings": {"duration": 5, "outdir": "C:/videos"}}: adds a shader (.glsl, .txt, .frag, .hlsl, .wgsl) to the queue and starts it; the job takes the general settings then its own; answer 201 with the job
GET /jobs{"jobs": [...]}
GET /jobs/{id}the job: id, path, state (queued, running, done, failed, cancelled), progress (frame, total, fps, remaining_s), error, outputs, log (the last 60 lines)
GET /jobs/{id}/outputs{"outputs": ["C:/videos/plasma.mp4"]}
POST /jobs/{id}/cancelstops the job (or removes it from the queue)
DELETE /jobs/{id}forgets a finished job
POST /shutdownstops the server

Jobs run one after the other, in order.

Example

$token = (Get-Content serve.token).Trim()
$h = @{ Authorization = "Bearer $token" }
$job = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/api/v1/jobs -Headers $h -ContentType application/json `
  -Body '{"path":"C:/shaders/plasma.glsl","settings":{"duration":5,"outdir":"C:/videos"}}'
Invoke-RestMethod -Uri "http://127.0.0.1:8765/api/v1/jobs/$($job.id)" -Headers $h

Complete clients that follow the progress: examples/automation/render.ps1 (PowerShell) and examples/automation/render.py (Python, standard library only). The self-test runs both against a real server.

Other machine-readable outputs

--progress=json prints one JSON object per line (start, log, progress, done, error, end), --report=json writes name.report.json next to each video, and --diagnostic prints key: value text lines. Their shapes are in schema.json (definitions progressEvent and renderReport).

Exit codes

0 everything rendered; 1 a render failed (also --serve on a port in use); 2 invalid command line; 3 no OpenGL 3.3; 4 ffmpeg not found; 5 benchmark slower than before; 6 --check warning; 7 --compare / --golden=verify / --verify difference; 8 newer version available; 9 --portability corrections exist.

ShaderToMP4 --serve[=port] démarre une API HTTP / JSON sur 127.0.0.1 (port 8765 par défaut). Elle est inactive tant qu'on ne la demande pas et s'arrête par POST /api/v1/shutdown. La forme de chaque réponse est décrite dans schema.json.

Accès

Le programme écrit un jeton de 64 caractères dans serve.token à côté du programme (et le port dans serve.json) ; les deux fichiers sont retirés à l'arrêt du serveur. Chaque requête doit porter :

Authorization: Bearer <jeton>
Host: 127.0.0.1:8765        (ou localhost)
CasRéponse
Pas de jeton, mauvais jeton401
Host autre que 127.0.0.1 / localhost, ou en-tête Origin (une page web)403
Adresse inconnue, travail inconnu404
Méthode non permise sur cette adresse405
Corps qui n'est pas du JSON, réglage inconnu, mauvais chemin400 ({"error": "..."})
Corps de plus de 1 Mo413
Trop de travaux en attente, suppression d'un travail en cours409

Le serveur n'écoute jamais sur une autre adresse de la machine et ferme toute connexion dont l'adresse distante n'est pas 127.0.0.1.

Adresses

Toutes sous /api/v1. Les corps et les réponses sont du JSON (UTF-8).

RequêteEffet
GET /status`{"program","version","api":1,"state":"idle""busy","queued","running","jobs"}`
GET /settingstous les réglages du tableau des réglages, en texte
PUT /settings{"width": 1280, "fps": 30} : change les réglages généraux (chaînes, nombres ou booléens) ; une clé inconnue donne 400 et ne change rien
POST /jobs{"path": "C:/shaders/plasma.glsl", "settings": {"duration": 5, "outdir": "C:/videos"}} : ajoute un shader (.glsl, .txt, .frag, .hlsl, .wgsl) à la file et la lance ; le travail prend les réglages généraux puis les siens ; réponse 201 avec le travail
GET /jobs{"jobs": [...]}
GET /jobs/{id}le travail : id, path, state (queued, running, done, failed, cancelled), progress (frame, total, fps, remaining_s), error, outputs, log (les 60 dernières lignes)
GET /jobs/{id}/outputs{"outputs": ["C:/videos/plasma.mp4"]}
POST /jobs/{id}/cancelarrête le travail (ou le retire de la file)
DELETE /jobs/{id}oublie un travail terminé
POST /shutdownarrête le serveur

Les travaux s'exécutent l'un après l'autre, dans l'ordre.

Exemple

$token = (Get-Content serve.token).Trim()
$h = @{ Authorization = "Bearer $token" }
$job = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/api/v1/jobs -Headers $h -ContentType application/json `
  -Body '{"path":"C:/shaders/plasma.glsl","settings":{"duration":5,"outdir":"C:/videos"}}'
Invoke-RestMethod -Uri "http://127.0.0.1:8765/api/v1/jobs/$($job.id)" -Headers $h

Clients complets qui suivent la progression : examples/automation/render.ps1 (PowerShell) et examples/automation/render.py (Python, bibliothèque standard seulement). L'auto-test lance les deux contre un vrai serveur.

Autres sorties lisibles par un programme

--progress=json écrit un objet JSON par ligne (start, log, progress, done, error, end), --report=json écrit nom.report.json à côté de chaque vidéo, et --diagnostic écrit des lignes de texte clé : valeur. Leurs formes sont dans schema.json (définitions progressEvent et renderReport).

Codes de sortie

0 tout est rendu ; 1 un rendu a échoué (aussi --serve sur un port pris) ; 2 ligne de commande invalide ; 3 pas d'OpenGL 3.3 ; 4 ffmpeg introuvable ; 5 banc d'essai plus lent qu'avant ; 6 avertissement de --check ; 7 différence de --compare / --golden=verify / --verify ; 8 version plus récente disponible ; 9 corrections possibles de --portability.
